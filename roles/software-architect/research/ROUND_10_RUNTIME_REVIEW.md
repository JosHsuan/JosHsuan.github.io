## What was expensive, and what remains unproven

Round 09's matched real-clock profiles found stable resource counts, not a demonstrated growing GPU leak. Camera-fit microbenchmarks were approximately 0.05–0.16 ms per held fit on this host; removing fit work cannot plausibly explain hundreds of milliseconds between delivered frames. Existing shader fill, optical gathers and browser compositing remain materially larger candidates. The Windows software-rendered browser profiles are not iPhone measurements.

Round 09 desktop warmed pixels fell from 399,466 to 155,160 because the scene was made physically and visually smaller. Restoring that 155k allocation across 1440×1000 would imply roughly .33 effective DPR rather than Round 08's warmed .53; fidelity would need explicit approval. On the profiled phone, Round 09 warmed pixels actually rose from 128,061 to 195,364 because pressure stayed at density 1 rather than .5. There is no universal 61% saving to preserve.

The current compositor owns an HDR RGBA16F scene color target, unsigned-int depth, optional MSAA, two quarter-resolution mist targets and a small glyph-cell target. Its estimate is:

`sceneWidth × sceneHeight × 12 × (samples + 1) + mistWidth × mistHeight × 16 + cellWidth × cellHeight × 8`.

This excludes the default drawing buffer, shadow maps, PMREM, geometry, browser compositing surfaces, decoded HTML images and process memory. Resource counts and this attachment formula are not total VRAM measurements.

## Safari mitigation and failure-path audit

The exact paths inspected are `components/CinematicScene.jsx`, `scene-compositor.mjs`, `renderer-budget.mjs`, `render-budget.mjs`, `render-pressure.mjs` and the root case/lifecycle integration. Source observations before Round 10 integration:

- A temporary WebGL2 capability probe created and deliberately lost an extra context before the real renderer. The integration removes it; the retained renderer and its error boundary now provide the capability test. The pinned Fiber 9.8.1 implementation catches renderer configuration rejection and propagates it through its error state to that boundary.
- Every device initially requested Full target MSAA 2 under a 1.6-million-pixel product cap. Density relief started only after warmup and sustained slow eligible delivery. A responsive GPU under memory pressure need not trigger that cadence policy.
- Native buffer assignment is guarded, including new-wide-width beside old-tall-height during orientation. Compositor attachments are reused when dimensions and sample count remain stable; cell storage is reserved independently of animated glyph-cell size. The integration retains these protections.
- Context loss, asset/initialization failure and caught frame failure route to semantic fallback and cleanup. A browser process termination cannot run this JavaScript cleanup or handler. Root therefore adds a persisted active-scene lease and failure preference so a subsequent load can show content and an explicit Enable 3D action instead of automatically repeating the failed path. Interrupted-load detection is a precaution, not a crash diagnosis, and normal page lifecycle/BFCache behavior must be tested for false positives. Confirmed failure remains latched for the tab session until explicit activation; queued heartbeat or pagehide cannot erase it. Only an uncertain unfinished active lease expires after 30 minutes.

The approved new pure `render-profile.mjs` provides a conservative coarse-pointer/iOS profile: Full 520,000 physical pixels, Light 360,000 pixels, no MSAA attachments and 512px shadow map. It detects iPhone/iPad/iPod and touch-capable desktop-mode iPad, without claiming to infer available memory. The standard profile retains 1.6M/1.2M pixels, MSAA 2 and 1024px shadow map. `render-budget.mjs` accepts a lower `pixelBudget` override but rejects anything above the normal product cap. Full materials, actual-source geometry, area-light direction and mist/DOF remain available.

At the previously measured 390×844 viewport, initial Full DPR remains exactly 1.25 and 513,785 pixels. Changing samples 2 to 0 reduces the existing attachment estimate from 19,084,908 to 6,754,068 bytes at the same dimensions, a 64.6% reduction in those attachments. This does not include the new page field or other resources. Its 2D backing at that viewport adds 1,316,640 nominal RGBA8 bytes plus a 258,048-byte atlas, before browser overhead. At the larger 430×932 CSS test viewport, the 520k cap reduces initial DPR from the unrestricted 1.25; actual browser chrome affects available viewport and must be recorded. MSAA removal and shadow resolution can affect edge/shadow quality and require visual inspection.

The stable mobile stage and page field retain their initial logical render height through height-only toolbar changes and update on width/orientation changes. No chapter transition writes drawing-buffer size. This reduces repeated storage replacement while restoring large visual composition. A real-device sustained check is still required before claiming Safari stability.

## Independent ASCII: agreed compositing contract

Scene/Lighting/Cinema initially proposed a decorative 2D page underlay behind transparent GL output. Integrated visual review found that the real exhibition wall/floor cover that underlay even with a transparent scene background. Root and scene roles therefore place the independent decorative field above GL and below readable HTML; they do not make the floor translucent to expose an effect. The scene compositor retains a subdued source-only response driven by actual radiance, depth and alpha. The global 2D overlay has no depth-derived attenuation and must remain restrained over source surfaces. Information/UIUX require it to remain visible when MAKE/VALIDATION sleeps the heavy GL scene, while HTML reading layers stay above both.

The previous production chapter path sets `asciiWeight: 0`; its actual source dependence came through `fieldSceneMix` inside the evolving field. Simply moving that field to 2D would lose source-derived behavior. The explicit split preserves a GL source-only response and moves only the independent contour/pointer field. No second GL context or per-frame readback is necessary.

The existing shader supplies seven analytic glyphs (`. : - + * # @`), two coherent evolving ribbon/contour functions, a two-lobe envelope and localized pointer curl. The 2D module ports those shapes/functions rather than using font glyphs or DOM nodes. It deliberately does not claim pixel-identical old scene blending: the old output combined scene-dependent normal/multiply/screen/soft-light terms, then Three's tone/color transforms. The independent 2D layer uses artist-reviewed display copper #e07b3b at 0.65 overall gain, 16 density bins and source-over compositing. The first ACES-converted trial appeared too beige/olive and too prominent over metal in synchronized captures; the reviewed display colour restores the copper field while retaining source priority. GL linear tint and source response remain unchanged.

`createPageFieldRenderer(canvas).render({field, frameTimeMs, paused, hidden, systemReduced}, width, height)` samples the artwork from `chapterScene.field.fieldTime` and limits delivery using `frameTimeMs`, supplied by the existing controller's RAF `tick(now)`. It owns no scheduler or clock. A finite nonnegative controller timestamp is required; there is no hidden fallback to accelerated story time. Limits are 900,000 physical pixels, a 4096px physical dimension, at most 12,000 evaluated cells and at most 30 time-driven updates per actual second. A genuine resize can refresh once at a stationary frame timestamp. Pause/hidden perform no drawing; Reduced/zero weight clears once; context loss disables work until restoration; disposal clears and releases both 2D backing stores. Optional context/atlas/drawing exceptions latch only the field off, with best-effort resource release, so the sole reading controller continues. Invalid developer arguments still throw. Diagnostics expose actual allocations, draws, cells, glyphs, dimensions, animation/frame timestamps, context state and failure reason.

The final static review found and corrected a cadence defect in the initial implementation: wheel/touch input can advance story time at 2.4× tempo, so a throttle based on `fieldTime` allowed 61 draws over one actual second at 60Hz controller delivery. The regression now provides separate timestamps and produces 31 draws including the initial frame at both 1× and 2.4× tempo, while the accelerated artwork still reaches its 2.4-second animation sample. No additional timer or RAF was introduced.

The detached 168×384 atlas pre-renders the seven analytic shapes at 24px into 16 density rows. The whole-page backing is capped at one physical pixel per CSS pixel before the area cap. Native width/height assignments also avoid a transient orientation overshoot. At 1440×1000 the authored 11px spacing would evaluate 11,921 cells; the cap increases spacing only for larger work envelopes. Full-page at 390×844 and 9px spacing evaluates about 4,136 cells. Trigonometry, envelope evaluation and drawImage calls remain genuine CPU work; the detached atlas does not make the field free.

Alternatives considered: a second WebGL renderer duplicates context/lifecycle pressure and is rejected. GPU-to-CPU depth readback adds synchronization and is rejected. A single full-screen GL output with an independently transformed scene texture could keep all field arithmetic on GPU and skip scene passes while absent, but introduces a different output/pointer-transform architecture and keeps full-page GPU work active. Retain it as an alternative only if this bounded 2D approach fails visual or measured performance acceptance.
