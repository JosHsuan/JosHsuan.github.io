# Software Architect / Runtime Engineer

This role was requested by the owner on 9 October 2026 to investigate sustained desktop/mobile failures and refactor the published Bending-Active presentation while preserving its successful material, lighting, camera and information design. It works with the Performance Engineer and Interactive Experience Director; it does not replace source-evidence, geometry or publication ownership.

The current software boundary is the isolated Bending-Active release. The empty portfolio framework, dependencies, authored source geometry and public story remain unchanged unless the owner explicitly expands the task. One camera writer, one active chapter clock, ordinary readable HTML, exact source provenance and the same-commit Pages validation gate remain mandatory.

The [Round 07 runtime audit](research/ROUND_07_RUNTIME_AUDIT.md) distinguishes source-level observations from measured results and crash hypotheses. Browser/device verification and final release evidence belong to the integrated case record, not an architectural assertion.

The [event and feature architecture research](research/EVENT_ARCHITECTURE_RESEARCH.md) compares GitHub implementations of typed events, commands, feature registration, decorators, selective state subscriptions and scoped cleanup. It proposes a staged Bending-Active runtime refactor while preserving the existing chapter clock and scene ownership; implementation remains a separate step.

The [advanced runtime patterns](research/ADVANCED_RUNTIME_PATTERNS.md) extend that direction with declarative plugins, coherent state commits, measurement scheduling, isolated workflow tests and optional render planning. Each pattern has an application-specific admission condition.

The [Bending-Active runtime architecture](research/BENDING_ACTIVE_RUNTIME_DESIGN.md) defines module boundaries, command/state flow, frame pipeline, registration lifecycle and migration sequence with diagrams. Its implementation mapping distinguishes the implemented core from optional decorators, actors and render planning. The [staged verification record](research/RUNTIME_REFACTOR_VERIFICATION.md) records tests, matched captures and measured limitations. The local implementation checkpoint excluded publication; the owner authorized commit, push and GitHub Pages deployment on 12 October 2026 through the existing validation workflow.
