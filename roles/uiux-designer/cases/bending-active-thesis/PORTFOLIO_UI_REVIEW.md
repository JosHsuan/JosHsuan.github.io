### Source and runtime handoff

- [PortfolioHome](components/PortfolioHome.jsx) and [portfolio styles](app/portfolio.module.css) currently own the two real card anchors and desktop / responsive grid. Keep the native project destinations and the shared root-layout `SiteExperience`; the card must not create a second site entry manager or delay essential HTML navigation while 3D is unavailable.
- [SceneRuntime](runtime/presentation/SceneRuntime.mjs) identifies `/assets/source-layers.glb` through the revision in [element-score](components/element-score.mjs), checks its metadata and assigns materials by `shell`, `base-lower` and `base-upper`. Its full initializer also loads chapter diagrams, captions and case lifecycle machinery, so it must not be mounted wholesale on Home. The card uses a separate bounded owner and dynamic import, with a static fallback.
- Match [cinematic material](components/materials/cinematic-material.js), the local `studio-small.hdr` environment and [CinematicScene's renderer output](components/CinematicScene.jsx): ACES filmic tone mapping, exposure 1 and sRGB output. [Continuous lighting](components/inspection-lighting.mjs), [chapter scene](components/chapter-scene-score.mjs) and [source scene pose](components/source-scene-score.mjs) supply the case recipe. Sharing only `scene-direction` constants is insufficient to claim the same final rig, because the case composes these samplers. The card may choose explicit stationary framing; record that difference rather than claim the case camera is unchanged.
- The accepted preview is one stationary live 3D owner within the card. Visibility / document-hidden / route teardown / context loss must abort pending work and release owned resources, with no permanent RAF, per-frame React state, duplicated Director, chapter clock or hover-driven model motion. Re-entry may render the same pose again; failure keeps a navigable static fallback. Any render-once derivative used as fallback must retain its actual source and recipe provenance.
- XR uses the owner-identified source animation selected and verified by the content role, not a simulated XR runtime. [ProjectAnimationPreview](components/ProjectAnimationPreview.jsx) shares [PreviewLifecycle](runtime/site/PreviewLifecycle.mjs) eligibility, acquisition deadline and terminal history with the model preview. Its [native-video adapter](runtime/site/video-resource.mjs) owns the silent, looped MP4 only while the element and document are visible, site entry has completed, neither Reduced motion nor Save-Data is active, and the user has not paused it. There is no GIF decoder, Blob URL, separate fetch or React playback clock. `Pause animation` / `Play animation` is an original icon button with that exact accessible name, outside the project anchor. Pause / offscreen / hidden / page exit / unmount aborts pending playback, pauses the video, removes its source and calls `load()` to release decoder work; a later eligible entry restores the saved native playback position. The shared 15-second deadline, guarded late `play()` resolution / rejection and static poster fallback close load failures. During loading the native video is renderable behind the opaque poster; readiness does not depend on starting playback inside a display-none element. The poster is eager, async-decoded and marked critical for the existing site-entry owner; optional video acquisition never blocks page readiness. The article and card use the same approved derivative and same-frame poster. No path or provenance is inferred from the old static hero.
- Animation diagnostics use `[data-project-animation-preview]`, `[data-animation-state]` (`poster`, `loading`, `playing`, `paused`, `failed`), `[data-animation-poster]`, `[data-animation-video]` and `[data-animation-toggle]`. The host's `__animationPreview.inspect()` reports shared request history, eligibility, user pause and saved position. A successful request retains one `ready` terminal when later disposed; a load timeout / failure has one `failed` terminal, and pending interruption has one `cancelled` terminal. A later playback error returns to the poster without inventing a second terminal for a previously completed acquisition. CPU resource tests are separate from built-browser playback / visual acceptance.
