# Home research specimen and project entry

## Authorized direction and baseline

The owner approved a more memorable, research-led homepage and coherent project-entry language on 24 October 2026. This candidate starts from published `bb602416962b558bb746ba71b89b393934f53279`; it does not resume the rejected Special Assemblies reading guide. Existing case narratives, assets, metadata, source links and author credits remain unchanged.

## One coherent exemplar

Home presents the original Bending-Active shell and two base layers as a research specimen beside the supplied introduction. Native document progress moves from the complete assembly through an authored, reversible orbit toward its openings/surface, then back to a composition accompanying the native Bending project link. The model is not deformed, exploded or presented as proof of physical performance. A featured link does not add a ninth project.

Desktop uses a bounded sticky visual beside two readable content beats. Mobile uses the native order identity → complete specimen → featured project entry → supplied long introduction and project-list shortcut, without a pinned scroll interval. The primary destination stays adjacent to its source instead of requiring a long prose detour; no original introduction text is removed. Reduced motion, SaveData, forced colors, missing JavaScript and bounded acquisition failures retain the original poster and native links. Eight project cards remain; Home's Bending card is a poster so it cannot acquire a second model. The standalone Projects route retains its original prepared preview.

## Ownership and cost

- Existing `SiteBackgroundDriver` remains the only ordinary-page demand clock. A registered Home presenter owns scroll progress; no second RAF or per-frame React state is introduced.
- Original asset verification, HDR/PMREM preparation, successful draw readiness, abort and disposal reuse the existing preview implementation. First-draw readiness includes the actual initial native scroll position.
- A one-time convex hull of the original support points yields 444 source vertices for camera fitting only; rendered geometry remains all 172,789 vertices. Resize preparation retains the exact source recipe. Scroll fitting uses those 444 extremes and up to 24 bounded centering iterations, rather than scanning the complete source; this costs more CPU than the initial eight-corner proposal and must pass the unchanged readiness/mobile gates. Source geometry, materials, lighting and asset bytes remain original.
- Home alone uses a transparent source layer: its three visible editorial-set meshes are omitted while original HDR, area lights, directional lights and all source/base meshes remain. No new floor/contact shadow is invented. The original opaque Projects preview remains unchanged. The decoded poster stays visible until a genuine successful first draw, then its paint is hidden beneath the transparent canvas.
- Candidate Home raster caps are 786,432 pixels for fine-pointer presentation and 393,216 for coarse-pointer presentation. These are explicit quality/performance tradeoffs pending actual image review, not an FPS guarantee.
- Subtle CSS sway is **2D presentation**, not 3D handheld or parallax. It stops offscreen, hidden, during Pause, focus, and static policies. Scene draws occur only when native scroll/size changes require a new pose.
- Pause freezes specimen presentation, never native document reading. Resume seeks current scroll progress rather than replaying missed movement.

## Native document continuity

The featured anchor remains a real `href`. Its existing validated navigation ticket can carry only the fixed `bending-active` presentation hint. Outgoing and destination loader compositions reuse the original poster while the background recedes. This does not transfer a GPU instance, mark the destination ready, delay navigation for animation, or bypass the Bending Director's independent readiness/reveal. Modifier/new-tab activation and unrelated routes do not receive the hint. Cancelled, superseded, timed-out and restored requests clear it.

## Site-wide grammar, not repeated decoration

This first exemplar establishes readable identity beside an authentic research subject, one authored explanatory reveal, and a source-related native entry. Subsequent projects should use their own evidence and composition rather than inherit Bending's metal aesthetic. No additional project effects are implemented by this slice.

## First-exposure and observation boundary

The second candidate, `ddcbf20`, passed 33 of 34 affected tests on each profile. Its sole automated failure was the newly added transition capture: Playwright locator checks or `page.evaluate` waited for navigation while that same test held the destination document. This was an observation deadlock, not evidence that native navigation or the loader was hidden. The bounded correction installs outgoing observation before navigation, transfers the actual ticket/paint facts to the host, and uses only the pinned implementation's non-stalling viewport screenshot while the document is held. Original bytes are then continued; the independently committed destination may hold its first model response for an arrival capture. All navigation/disposal/history assertions and the existing scenario budget remain; 120 seconds locally is 240 seconds under the existing CI multiplier.

Actual WebKit pixels also exposed a separate production gap: the initial hero was blank, although preparation had completed; later scroll and the identical returned pose were visible. Prepared rendering occurred under the entry cover, and pose deduplication suppressed a new commit when the page actually became exposed. The correction distinguishes preparation from one successful first-exposure draw per acquisition generation, on the existing driver clock. It requires actual entered state, a connected visible canvas, the real loader hidden/display-none, a current active resource, and no hidden/disposed/paused/static state. It does not add a timer, RAF, ongoing redraw, or buffer-setting workaround. The precise browser compositor mechanism is not established; an exposure counter alone does not prove visible pixels. New initial and Back captures remain mandatory. Retained hidden/BFCache resources do not acquire repeated exposure commits.

New controls and captions use the established 14-pixel control and 12-pixel label roles, with the existing body/caption tokens rather than undersized custom text. The new mobile composition and transparent detail views were independently judged materially clearer than the original baseline; complete visual acceptance, transition continuity and exact release gates remain pending.
