## Approved scope

This candidate reuses the published hybrid presentation from Special and HC3DP: native Overview, Results and Credits, with adjacent glass reading surfaces and their existing velocity feedback. It is a source-composition change, not a new camera, depth effect or reconstructed fabrication sequence. The production baseline is 64e; this candidate has not yet received actual-image or release qualification.

## Bounded source sizing

Actual original files confirm that only the two Results photographs are 1024 pixels wide; the opening hero is 2560 pixels wide. The shared native figure currently permits a 1141 CSS-pixel width. The implemented minimal correction is a Dot-only, Results-only `.scene` maximum of 1024 CSS pixels, retaining the existing responsive `width:100%`, intrinsic aspect ratio and complete-image rendering. It adds no JSX fork or new component prop and leaves Cas, Special and HC3DP selectors and geometry unchanged. The opening keeps the shared layout.

This is a CSS display-width ceiling, not a promise of one source pixel per device pixel on high-DPR screens. Original softness, lighting and limited photographic detail remain; the original-image action is the authoritative full-source access. Source review confirms the selector requires both the Dot project root and native Results root; both non-diagram Results figures retain the existing `.scene` class. The opening is outside this selector. Actual rendered sizing remains a browser acceptance requirement.

## Required acceptance and limits

Before broader qualification, actual desktop/mobile originals must show a useful image-first opening, complete Results photographs, readable adjacent prose/captions/credits and unobstructed source actions. Confirm the two Results images do not exceed the source-width ceiling, without cropping or changing other published routes. Compact typography, glass focus neutrality, reduced/static/no-JavaScript reading and source-failure access remain required.

The hybrid journey must separately retain System's original points and camera, Making's original looping recording, native Results/Credits ownership and reverse return to System without leftover movie or photograph ownership. Do not infer lifecycle correctness from static PNGs, recording advancement from a still frame, or same-lease continuity across independent test contexts. Fresh history behavior must follow the existing published policy; no new navigation delay is proposed.

Source review, actual composition captures, affected qualification and the required full release gate are pending. No performance improvement, hardware FPS, image-detail enhancement or publication is claimed by this plan.

The initial C/mobile qualification plan uses separate native-photo and same-page lifecycle scenarios: 90 and 120 seconds respectively (the existing CI multiplier yields 180/240 wall budgets). This does not change the production 15-second entry deadline or existing 45-second waits. The two independent contexts cannot establish a shared lease across cases; model/movie/Results/reverse ownership must be proved within the lifecycle case itself. No actual run result is recorded here yet.
