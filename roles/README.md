# Isolated role workspaces

These workspaces preserve the successive research, specialist tooling and local integration phases. The production application remains the empty framework. Role dependencies, opt-in Codex homes and MCP registrations are separate; normal root builds do not install or activate role tooling.

| [Bending-Active Thesis case](uiux-designer/cases/bending-active-thesis/README.md) | Seven-chapter cinematic integration of the specialists' work | `http://127.0.0.1:4184/` |

The review servers are opt-in local processes, not hosted deployments. Each role README describes its pinned tools, build commands, licences and verification limits. Existing test reports are dated evidence; a new checkout does not imply a fresh successful test run.

Version control retains source code, original specimens, licensed public reference assets, role skills/configuration templates, documentation and sanitized verification summaries. It excludes dependencies, generated builds, runtime homes, credentials, private source audits, thesis narrative/media/model handoffs and geometry-derived framing support. Do not force-add ignored local data when preparing a commit.

The thesis case is intentionally not self-contained in a fresh clone. An authorized local handoff must supply its ignored content snapshot, assets and private framing module. Working material preparation remains under `D:\JosHsuan_Website`; the build reads prepared local copies rather than scanning that drive. A Git push is separate from the manually dispatched Pages deployment workflow.
