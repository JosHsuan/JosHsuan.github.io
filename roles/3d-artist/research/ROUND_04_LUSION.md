## Critique of the current implementation

The existing presentation has a coherent source-presence sequence, actual depth-based focus, bounded scene-derived ASCII, local highlight diffusion and a validated satin finish. More bloom, a lower roughness value or another camera sweep would not add a new way to understand the work. The supplied curved normals and holes still make small highlights; erasing them would falsify the source. The approved model has three source layers, 172,789 vertices and 227,521 triangles, with no verified flat-panel parametrization, UV rolling direction or structural response field.

Two limitations are actionable. First, the scene is mostly observed through an authored story: readers cannot deliberately compare a high view, the original placement and the separated source layers. Second, the exhibition rig follows the camera. If this behavior were retained while the reader rotates the inspection camera, the main highlight would keep facing the viewer, weakening the relationship between viewing angle and surface response. The new mode therefore needs source-fixed light directions and stable framing before any more elaborate material treatment.

## Cross-role agreement and architecture

Motion Designer owns a single controller-driven response state. Parent-owned DOM events set target values; the existing tick advances them. No OrbitControls, second requestAnimationFrame or independent smoothing enters the camera module. Reduced motion keeps direct inspection controls functional and adopts targets immediately, rather than forcing the story's dimmed CREDITS view.

Cinema supplies `sampleInspectionPose({bounds, aspect, azimuth, elevation, viewport})`. The final agreed neutral is 30°/30°, azimuth bounds −40° to 100°, elevation 12° to 70°. Named views are Front 0°/18°, Three-quarter 30°/30°, and High 30°/65°; “High” is not an orthographic top view. The pure resolver returns the existing pose fields and normalized view offset. The parent World remains the only camera writer. Enter/exit switch modes directly; Return/Escape restore the captured story state and scroll position without replaying a camera flight.

The viewport is the unobscured drag region normalized to the full Canvas, measured by the parent from the actual responsive layout. Its center becomes the optical composition center. The fixed original-plus-maximum-separation envelope is fitted with perspective depth and 3% inset on each viewport edge. The original implementation fitted its box corners; the visual iteration below replaces those empty corners with verified actual-source convex support. The vertical FOV is 36° and must not receive the story's optical lens multiplier afterward. Fit distance can respond to viewing angle; changing separation alone does not change camera inputs or position. No source positions/normals/bytes are rewritten.

Lighting/Scene Designer agreed to separate the source-frame light directions from any camera-facing background geometry. The existing shadow key follows the same authored light direction; rectangular lamps are not falsely presented as shadow casters. Inspection disables DOF, ASCII and mist to make visual comparison clear. It retains the original PBR surface. Silhouette is explicitly an outline study, not a material calibration. Root owns native dialog behavior, keyboard/focus return, scroll hold, measured viewport and final scene bindings.

## First integrated inspection and source-framing correction

All six first-build `desktop/mobile` × `studio/raking/silhouette` captures were opened as images. Studio makes the whole surface readable; Raking separates illuminated folds from the darker body; Silhouette clearly exposes the actual outline and perforations. The initial pale header on the silhouette background needs darker text, and an inactive light-angle control should not imply an effect. The parent owns those interface corrections. This review does not suggest a brighter glow or a changed normal field to compensate for the source's apparent size.

The initial model was visibly too conservative for inspection, especially on the phone. The stored actual pose/viewport was used to reproject every source vertex independently. Predicted rest-placement spans exactly match the screenshots: **522.4 × 450.1 px** inside the desktop's 1018 × 833.5 px clear box, and **203.4 × 165.8 px** inside the phone's 358 × 354.5 px box. This establishes that the mapping is correct; empty bounding-box corners cause the wasted space. Per-layer boxes provide almost no improvement. Fitting the original/max-separated actual source support predicts **631.9 × 558.5 px** desktop and **300.6 × 250.2 px** phone, still without changing the separation-dependent camera inputs or 3% safety inset.

The parent approved an explicit Geometry Engineer review of a derived framing support set from the already-public release GLB. `scripts/prepare-inspection-framing.mjs` reads only that approved GLB/minimal metadata and the known rigid layer offsets. It verifies the full source SHA and counts, transforms every vertex through its source node matrix, and computes the installed Three **0.186.1** convex hull of both separation endpoints: **345,578 input positions → 514 support points / 1,024 hull faces**. Linear intermediate layer placements are contained by this fixed endpoint hull. Coordinates retain their JavaScript double values with no rounding, decimation, smoothing or modification of the GLB.

The generator first writes the module and manifest to `D:\JosHsuan_Website\_work\bending-active-thesis\round-04\prepared`, followed by an explicit reviewed handoff into `components/inspection-framing-support.mjs`. Its `INSPECTION_FRAMING_SUPPORT` export contains the full source SHA, endpoint/count provenance, exact maximum offsets and frozen point arrays. The checked-in module is **42,571 bytes**, SHA-256 `84e5c828e4a788577d6ca8a29eb539332b284763a2087a48a44abc2bca96c53a`. It is small JavaScript geometry metadata, not a texture or another rendered mesh. Normal builds use the module and do not read the D drive or run the hull generator.

`sampleInspectionPose` now accepts optional `framingSupport`. It verifies the support's pinned source SHA and containment within the fixed envelope, then uses its points for the perspective fit. The original bounds retain target and clip-plane responsibility and remain the generic no-support fallback. The parent supplies this one constant to the existing single camera writer. Current camera SHA-256: `f2dad988f2ca88e9ef0c1540ff3bb7e53062ea497a680587bc75a345e233c583`.
