# 0019 - Portfolio materials, six-case design and runtime refinement

Date: 20 October 2026 (Europe/Berlin).

The owner requests six connected outcomes through GitHub Pages publication:
correct Caschlatsch's images using the original portfolio, replace Mode/s's
large recordings with compact excerpts no longer than ten seconds, redesign
the six other project pages' UI/UX, motion and interactions to the quality of
Bending-Active and XR, then have the senior web architecture role refactor event
ownership/performance while preserving the resulting visual effect, and finally
rewrite the root README around the actual architecture with suitable primary
GitHub/web references. All twelve existing team roles must participate.

This supersedes the rejected Caschlatsch public-workflow/ETH image selection
and the previous Mode/s web derivatives' complete-sequence/remux/pixel-size
requirements only for these explicitly requested replacements. Original source
files remain read-only. A web transcode must disclose its actual source interval,
dimensions, timing, encoding and measured quality; compressed pixels cannot be
described as byte-identical to the original. Other source contracts remain.

The sequence is source correction and media optimization, six-case UI/UX and
motion/interaction implementation, senior event/performance refactoring,
architecture-led README, then final validation/publication. Independent source
review and design/research may proceed in parallel. Bending-Active and XR remain
protected visual references and require matched regression when shared code
changes. The empty reusable `src` framework, source geometry and camera/material/
lighting recipes, native readable content, one Director clock and the existing
same-commit/same-artifact deployment gate remain protected.

The owner authorizes implementation, tests, commit, push and CI-gated deployment
through completion; no further publication approval is required for this scope.
The [integration contract](../../roles/uiux-designer/cases/bending-active-thesis/PORTFOLIO_REFINEMENT_INTEGRATION.md)
defines the concrete work and acceptance. Historical records retain their old
candidate identities; their success does not accept this new implementation.
