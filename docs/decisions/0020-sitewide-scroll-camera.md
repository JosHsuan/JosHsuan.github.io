# 0020 — Site-wide refinement and scroll-led camera direction

Date: 22 October 2026. Status: authorized implementation; route acceptance is
tracked separately in the coverage matrix, not implied by this decision.

The owner asks that the previously discussed visual/interaction principles be
planned across the entire site, not delivered as unrelated case polish. Native
scrolling should lead authored camera paths and shots instead of requiring a
click-and-hold rotation gesture. Preserve the appreciated idle handheld
micro-motion and continuous movement between sections. Ordinary engineering and
release decisions are delegated, subject to source preservation, access controls,
exact-artifact CI and verified publication.

This supersedes older fixed-camera presentation constraints only for the reviewed
scroll-camera adapters. Original geometry, materials, lights, reference views,
source recipes and assets remain protected. Bending's independent idle/source
score is not replaced by scroll time; XR recordings keep native media time.
Each existing presentation owner remains the sole scheduler/final camera writer.
No added animation loop, compulsory inspection UI or fabricated scene is implied.

Implement and accept a generic adapter first, then explicit XR and Bending
adapters. All model-bearing routes belong in the plan; Caschlatsch currently has
no 3D model and must not acquire an invented one. Glass-panel motion remains a
separate rollout: the Mode/s pilot is not evidence of global implementation.
Global Roboto Mono typography is an earlier accepted shared layer.

See the [camera direction](../../roles/uiux-designer/cases/bending-active-thesis/SCROLL_CAMERA_DIRECTION.md)
and [site-wide matrix](../../roles/uiux-designer/cases/bending-active-thesis/PORTFOLIO_SITEWIDE_COVERAGE.md).
Acceptance requires actual source framing, native forward/reverse and mobile
reading, keyboard alternatives, focus, Pause/reduced-motion, lifecycle/resource
continuity, independent idle and measured performance. Source tests and
software-browser captures do not establish physical-device frame rate. Preserve
unresolved diagnostics rather than declaring a prior intermittent failure fixed
because a later run passed.
