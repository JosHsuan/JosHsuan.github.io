# 0013 — XR background scene and continuous glass narrative

Date: 16 October 2026 (Europe/Berlin).

The owner accepts the existing XR research content and narrative but requests a
different presentation: study Bending-Active through every existing team role,
then implement its background-scene / floating-information approach for XR.
The XR project card must center both original phones and inset its image slightly
to expose its glass surround. Implementation, testing, commit, push and the
existing exact-artifact GitHub Pages deployment are authorized through completion.

This supersedes the XR revision's boxed model/phone viewers and disclosure-first
supplementary evidence. It does not authorize changes to the approved Bending
case, source geometry/materials, common background, empty reusable framework,
private-source boundaries or pinned toolchain.

## Adopted composition

One project-local `XRStageDirector` selects native reading chapters, manages
inspection intent, one demand scheduler and the existing information-window
presenter. One transparent fixed WebGL stage owns the XR camera, original bamboo
assembly and phone display. It does not mount Bending's full Director or scene.
Layer 1 remains the separately owned shared CSS/vignette/Canvas 2D background;
Layer 2 is semantic HTML and standard glass reading windows; Layer 3 is XR's
project-owned model and phone. Nothing is moved into the global background lease.

Native scroll is the reading authority. Adapt, Assemble and Join are three real
consecutive sections, each selecting its complete original recording without a
tab, disclosure or camera button. Video time remains the native media clock;
decoded frames invalidate the same stage rather than creating a second JS clock.
Model camera gestures require an actual source hit and preserve native vertical
touch reading. Semantic keyboard inspection is scoped to the model aperture.
There is no zoom/reset/face-screen button group or autonomous model orbit.

Reading text stays outside material distortion. The existing `InformationSkin`
and standard material tokens provide the Bending information treatment, with
native contrast/transparency and no-JS fallbacks. Optical controls remain scoped;
this request does not apply refraction to source diagrams, photographs or text.
All principal evidence is visible in ordinary document flow; archival media
retains a direct source link instead of adding another foreground video player.

## Resources, source fidelity and acceptance

One renderer/camera is shared between model and phone chapters. Inactive media,
video textures and pending acquisitions are cancelled/released. Hidden, page,
preference and disposal transitions have explicit terminals. Reduced Motion and
Save Data preserve honest source posters and recording links without compulsory
model/video downloads; unavailable/lost WebGL retains readable native media.
Native pause/resume preserves recording position.

The GLB, original material, normals, source transform, all three full recording
sequences and research attribution remain pinned. The XR card adjustment is a
scoped framing change; it does not edit the image bytes or Bending card.

The [actual team review](../../roles/uiux-designer/cases/bending-active-thesis/XR_IMMERSIVE_TEAM_REVIEW.md)
records four collaborating agents covering all twelve existing responsibilities.
Verification must inspect actual desktop/mobile rendering, native controls,
chapter transitions, absence of disclosure/button detours, single-stage budgets,
media timing/fallback/disposal and the protected Bending presentation. Run the
exact toolchain, `pnpm check`, relevant portable/browser checks against built
output, then the same-SHA CI gate and deployment of that tested artifact. A
successful build or planned test is not publication evidence. This decision
records the implementation direction, not completed acceptance.
